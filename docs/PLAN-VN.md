# NIKKE 式剧情演出：立绘 + 差分 + 对话框 + 战场背景

> **历史文档，仅作背景。**
> 当前实现状态、验收数字与已知限制一律以 [`HANDOFF.md`](../HANDOFF.md) 和 [`README.md`](../README.md) 为准；
> 本文描述的是当时的计划或审计快照，其中的版本号、文件路径和行为可能已经变化。

> 版本：讨论稿（未实施）
> 结论：**同意，这是当前性价比最高的叙事方案。** 但「立绘 + 对话框」本身不等于表现力，
> NIKKE 真正起作用的是**镜头、节奏、差分切换、语音**；我们复制前三样，第四样用音效与文本节奏补。

---

## 1. NIKKE 到底做对了什么

| 要素 | NIKKE 的做法 | 我们能复制吗 |
|---|---|---|
| 2D 立绘 + 差分 | 大量表情差分，角色站在场景里说话 | ✅ 核心 |
| 对话框 | 底部半透明框、名字、逐字、语音 | ✅ 去掉语音 |
| 镜头语言 | 推近、横移、抖动、黑边、眼部特写 | ✅ CSS 就能做 |
| 关键 CG | 少数高规格全屏插画 | ✅ 用 ImageGen 补 |
| 全语音 | 主线全程配音 | ❌ 成本太高，先不做 |
| Live2D | 角色会呼吸、眨眼、轻微摆动 | ⏳ 先用程序化/差分替代 |
| 竖屏 | 信息少、注意力集中 | ✅ 手机端天然适合 |

**关键认知**：NIKKE 的立绘并不是「站着不动」——它有呼吸、眨眼、镜头推拉、说话人高亮、
黑边和音效。我们如果只是把一张 PNG 放进弹窗，观感会立刻掉到「PPT」。
所以这个 plan 的重点不是「画多少张」，而是**把舞台做出来**。

## 2. 我们的 VN Stage（一套，不是每个场景一套）

全屏剧情层，DOM 实现（文字清晰、手机友好、零 WebGL 成本），叠在游戏之上：

```
┌──────────────────────────────────────────────┐
│  [背景层]  远景 / 中景 / 前景（视差）           │
│                                              │
│        [角色 B]        [角色 A]               │
│        （暗 15%）      （说话人高亮）          │
│                                              │
│  ┌────────────────────────────────────────┐  │
│  │ 白垩                         AUTO 跳过 记录│  │
│  │ 「这不是拍卖，这是分赃。」                 │  │
│  │                                  ▼      │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
```

### 2.1 画面规格

- **背景**：2–3 层（远景 / 中景 / 前景雾），按 `data-depth` 做 6–14px 的视差；
  切场景 400ms 交叉淡入；关键行可加黑边（上下各 7vh）。
- **角色**：最多 3 人同屏（左 / 中 / 右），底部对齐；非说话人降亮度 15%、去饱和 10%；
  入场从侧边 12px + 淡入 240ms；退场反向。
- **对话框**：底部 28vh（手机 34vh），名字用角色主色，正文 16px（手机）/ 17px（桌面）；
  逐字 35–45 字/秒，句号停 120ms，省略号停 300ms；点击一次补全、再点下一句。
- **镜头**：`push`（推近 1.06）、`pan`（横移 ±24px）、`focus`（对某个角色 1.12 倍）、
  `shake`（3px/180ms）、`insert`（全屏道具/眼部特写 0.8s）。全部 CSS transform，不碰 WebGL。
- **控制**：`AUTO`（1.8s 自动）/ `跳过`（整场）/ `记录`（回看已读文本）/ 隐藏 UI（截图用）。
- **手机**：竖屏优先，角色半身构图，对话框贴底 + 安全区；桌面 16:9，两侧留暗。

### 2.2 代码结构

```
web/js/vn.js        ~500 行：舞台、镜头、逐字、差分、存档、预载
web/css/vn.css      ~300 行
web/data/story.js   剧本数据（纯数据，不写逻辑）
web/assets/vn/      立绘差分 + 背景 + CG
```

对外 API：

```js
VN.play(sceneId, { onDone });   // 整场对话
VN.bark({ who, portrait, text }); // 战斗中的一句话（不锁输入）
VN.insert({ image, title, subtitle, duration }); // 觉醒/大招/Boss 蓄力
VN.skip(); VN.isActive();
```

## 3. 剧本结构：13 场，约 130 句

不写 2 万字。先把「三幕的骨架」写清楚，每场 8–12 句、60–90 秒：

| # | 场景 | 内容 | 角色 |
|---|---|---|---|
| 1 | 序章 | 雨夜接单，协议第一次开口 | 队伍 2 人 + 旁白 |
| 2 | 第一幕开场 | 拍卖行的请柬 | 队伍 2 人 |
| 3 | 拍卖人 · 战前 | 他把记忆拆成盲盒 | 拍卖人 + 队伍 |
| 4 | 第一幕收尾 | 锤子落地，核心还在跳 | 队伍 |
| 5 | 幕间一 | 邀请函上的名字被改写 | 队伍 2 人 |
| 6 | 第二幕开场 | 穹顶的镜子记得每个人 | 队伍 2 人 |
| 7 | 执政官 · 战前 | 责任被无限分摊 | 执政官 + 队伍 |
| 8 | 第二幕收尾 | 一万片礼貌的微笑 | 队伍 |
| 9 | 幕间二 | 轨道电梯上升 | 队伍 2 人 |
| 10 | 第三幕开场 | 零号轨道，没有回声 | 队伍 2 人 |
| 11 | 主脑 · 战前 | 永远在开会的房间 | 主脑 + 队伍 |
| 12 | 第三幕收尾 | 把世界从桌上拿下来 | 队伍 |
| 13 | 结局 | 城市在没有锤声的早晨醒来 | 旁白 + 队伍 |

另外：

- **精英**：6–9 条「名字 + 一句威胁」，进场时用 `VN.bark`，不打断操作。
- **Boss 战中**：75% / 50% / 25% 各 1 句，死亡 1 句；共 12 句。
- **觉醒**：16 段 4–5 句的短场景 + 1 张 CG（V4 再做）。
- **支线**：沿用现有任务文本，不扩 VN。

### 3.1 一个必须先解决的设计问题：队伍是玩家选的

NIKKE 是固定角色，我们是 16 选 4。如果每场戏都让「当前队伍」说话，就要为 16 个角色写
不同语气、做 16 套差分，写作量会爆炸；而且玩家可能带着三个沉默的陌生人在看戏。

**建议：主线用「固定叙述者 + 3 个 Boss + 2 个固定 NPC」承担戏剧冲突，队伍只负责「角色化反应」。**

- 队伍台词写成**角色无关**的短句（按位置 / 职能分配），每人只需 2 个表情：平静 / 严肃；
- 角色个性放在**觉醒场景**里（每人 4–5 句 + 1 张 CG），那里才是「他是谁」的地方；
- Boss 与 NPC 是固定角色，差分做足（3 个表情/状态）。

这样既不会让 16 个角色都变成纸片，也不会把写作量乘以 16。

## 4. 差分立绘：数量与管线

### 4.1 数量（先做能撑起 13 场戏的最小集）

| 类别 | 数量 | 说明 |
|---|---|---|
| 队伍基础 | 16 × 2 = 32 | 平静 / 严肃；现有立绘做 master |
| 主角加差分 | 4 × 2 = 8 | 微笑 / 愤怒；给戏份最重的 4 人 |
| Boss | 3 × 3 = 9 | 常态 / 受损 / 暴走（可用同一张 + shader 裂纹） |
| 通用情绪符号 | 6 | 汗、怒筋、阴影、红光、问号、省略号 |
| **合计** | **约 49 张** | 不含觉醒 CG 与大招 cut-in |

### 4.2 管线（`tools/art/vn_sprites.py`）

1. **归一化**：现有 16 张立绘尺寸不一（373×679 到 634×1137），先 trim alpha，
   统一到 1024×1536 画布、底部对齐，记录**眼线高度**与**头高**。
2. **生成差分**：以 master 为 `image1`，`input_fidelity: high`，
   prompt 只改表情、不改构图：
   > same character, same pose, same camera, same costume and lighting; change only the facial expression to {expression}; no text, flat magenta background (#FF00FF)
3. **抠图**：沿用 `tools/art/keyout.py`（纯色底 flood fill），输出透明 WebP。
4. **验收**（每张都过）：
   - 身份：发际线、眼距、下颌、服装不变；
   - 登记：眼线 / 头高与 master 差 ≤ 2%；
   - 表情：在 360px 宽度下仍能读出情绪；
   - UI：对话框不遮脸，不超出安全区。
5. **命名**：`web/assets/vn/{charId}/{expr}.webp`；metadata 记录 `eyeLine / headHeight / anchor`。

**不要**拿「笑」去生成「怒」，再拿「怒」去生成「哭」——误差会累积。每次都从 master 出发。

### 4.3 如果差分不稳定

降级方案（仍然成立）：**master + 通用情绪符号**（汗/怒筋/阴影/红光）+ 镜头推近。
NIKKE 的表情很细，但我们的文本与镜头可以补；不要为了 16 套完美差分把项目拖死。

## 5. 背景与战场

### 5.1 剧情背景：12–14 张

| 幕 | 场景 |
|---|---|
| 通用 | 雨夜街道、安全屋、旧网终端、黑市 |
| 第一幕 | 拍卖行外、拍卖厅、后台金库 |
| 第二幕 | 镜海穹顶、镜廊、淹没的观众席 |
| 第三幕 | 轨道电梯、零号走廊、会议室、地球舷窗 |
| 结局 | 清晨的霓虹港天台 |

- 1280×720（手机端裁 9:16 安全区），WebP q84，单张 100–150KB；
- 统一色调：青 + 洋红 + 深蓝，和现有 key art 一致；
- 每张留出「角色站位」：左右下角不要放高对比细节。

### 5.2 战场背景：3 张 Boss 竞技场（这是最大的一眼提升）

现在战斗只有玻璃棋盘 + 雾，没有「地点」。给三个 Boss 各做一张 1920×1080 的竞技场背景：

- 拍卖厅（聚光灯、观众席剪影、吊灯）；
- 镜海穹顶（镜面穹顶、积水倒影、碎裂的吊灯）；
- 零号会议室（环形长桌、黑色巨石、舷窗外的地球）。

接入 `battle3d.js`：在棋盘后方 z = -9 放一张大 plane，`MeshBasicMaterial` + 低透明度 + 雾，
相机移动时按 0.2 倍位移做视差；Boss 二阶段换一张同场景的「受损/红色警报」版本（可用 shader 调色，不必新画）。
**这张背景会让所有 Boss 战立刻从「棋盘」变成「战场」。**

## 6. Boss 战演出（NIKKE 式）

### 6.1 战前

- 进入 Boss 节点 → `VN.play('act1_boss_pre')`（7–8 句，Boss 立绘居中、队伍在两侧）；
- 最后一句 → 黑边收拢 → 进战斗；
- 联机：房主触发，其他人看同一场；跳过需房主确认（V2）。

### 6.2 战中台词

- 底部出现**窄对话框**（不遮棋盘），Boss 小头像 + 一句话，2.8 秒自动消失；
- 触发：75% / 50% / 25% / 死亡；**不锁输入**，不暂停回合；
- 台词内容给机制提示，而不是纯氛围：
  「这具身体里还有 37 份没卖出去的记忆。」（暗示护盾）
  「别碰镜子——它会替你回答。」（暗示反射）

### 6.3 二阶段（实时，不用视频）

1. 血量 ≤50%：0.15s 去色 + 0.2 倍速；
2. Boss 立绘切「受损」差分 / shader 裂纹 + 竞技场背景变红；
3. 1.2s 横幅：`第二阶段 · 协议覆写` + 一句台词；
4. 技能表切换，音乐加一层。
   **总锁输入 ≤0.6s**，其余时间照常操作。

### 6.4 Boss 大招

- 1.2s 全屏 cut-in：Boss 立绘 + 技能名 + 红黑速度线，然后回到战场结算；
- 与玩家大招 cut-in 共用 `VN.insert`，不另写一套。

## 7. 技术接入

### 7.1 触发点

| 位置 | 现在 | 改成 |
|---|---|---|
| 开场 / 换幕 | `pendingBeat` → 文字弹窗 | `beat.scene` → `VN.play`；没有 scene 时保留旧弹窗 |
| 幕间 | `Cine.act` 整幅图 | 先 `VN.play('interlude1')`，再 `Cine.act` 进下一幕 |
| Boss 进场 | `Cine.encounter` | 先战前 VN，再 `Cine.encounter` |
| 精英 | 无 | `VN.bark` 1 句 |
| 觉醒 | 文字卡 | `VN.insert` 觉醒 CG + 4 句独白 |
| 大招 | 无 | `VN.insert` 0.9s |

### 7.2 数据格式

```js
export const SCENES = {
  act1_boss_pre: {
    bg: 'auction_hall',
    bgm: 'explore',
    cast: [
      { who: 'boss_auctioneer', slot: 'center', expr: 'normal', scale: 1.1 },
      { who: 'p1', slot: 'left', expr: 'serious' }
    ],
    lines: [
      { who: 'boss_auctioneer', expr: 'smile', text: '欢迎来到本世纪最后一场拍卖。' },
      { who: 'p1', expr: 'serious', text: '我们不是来竞拍的。', fx: 'shake' },
      { fx: 'insert', image: 'assets/vn/cg/auction_hammer.webp', duration: 0.8 },
      { who: 'boss_auctioneer', expr: 'angry', text: '那就把你们自己押上来。', letterbox: true }
    ]
  }
};
```

- `who: 'p1'..'p4'` 在运行时解析为当前队伍成员；
- `expr` 缺省回退到 `neutral`；
- 说话人切换时只换图，不做布局位移（差分已归一化）。

### 7.3 联机与存档

- **V1 只在单人播完整 VN**；联机用 1 句 bark + Boss 进场横幅，避免三个人等一个人看字。
- V2 再做同步：`GameState.StoryScene` + `advanceStory` 动作，房主推进，其他人跟随，跳过需房主确认。
- 已读场景记在 `GameState.SeenScenes`，二周目可跳过；「记录」可回看。

### 7.4 性能

- 纯 DOM + CSS transform，不增加 WebGL 上下文；
- 立绘按幕懒加载：进幕只预载「队伍 4 人 + 本幕 Boss + 2 个 NPC」；
- 单张 WebP 150–250KB，一幕增量 < 3MB；
- 背景切换用 `decode()` 预解码，避免第一帧空白。

## 8. 阶段与验收

| 阶段 | 内容 | 验收 |
|---|---|---|
| **V0 垂直切片** | 序章 10 句、2 角色、1 背景、2 表情；完整舞台（镜头/逐字/跳过/记录） | 手机 390×844 能读能点；60fps；跳过 <0.2s；不像 PPT |
| **V1 资产** | 16×2 队伍差分 + 4 主角各 +2 + 3 Boss 三态；12 张背景；3 张竞技场 | 差分眼线/头高误差 ≤2%；背景切换无白帧 |
| **V2 剧本** | 13 场 × 8–12 句；精英 bark；接入 `pendingBeat` / 幕间 | 每幕开场到可操作 ≤90s；可全程跳过 |
| **V3 Boss** | 战前 VN、阶段台词、二阶段、Boss 大招 cut-in | 阶段横幅 ≤300ms；锁输入 ≤0.6s；不打断联机 |
| **V4 角色时刻** | 16 段觉醒独白 + 16 张 CG；16 个大招 cut-in | 可跳过；设置里可关大招 cut-in |

**总资产量级**：约 49 张差分 + 14 张背景 + 3 张竞技场 ≈ 66 张图；
按 5–10 积分/张，约 **330–660 积分**（不含觉醒 CG / 大招 cut-in，那批再加约 32 张）。

## 9. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 差分一致性差（脸变了） | 出戏，比不做还糟 | master 归一化 + 每次从 master 生成 + 360px 验收；不行就用符号降级 |
| 队伍是 16 选 4，写不出个性 | 台词像广播 | 主线用固定 Boss/NPC 承担冲突，队伍只做反应；个性放觉醒 |
| VN 太长，打断节奏 | 玩家跳过，等于没做 | 单场 ≤90s；每幕 ≤2 场；可跳过；联机只播 bark |
| 背景与立绘风格不统一 | 拼贴感 | 统一色调与笔触，背景加雾/暗角，立绘加边缘光 |
| 手机字体与安全区 | 读不清 | 16px 下限、底部安全区、最大 3 人同屏 |
| 角色差分数量失控 | 项目拖死 | 先 16×2，主角 4×2；觉醒 CG 分期 |

## 12. 已落地（0.19.0）

这一版没有完全按本文的 13 场 × 8–12 句铺满，但把**舞台和主线的骨架**做完了：

| 计划项 | 实际 |
|---|---|
| 全屏 VN 舞台 | `web/js/vn.js`，DOM；最多 3 人；非说话人压暗；说话人推近 |
| 镜头 | `wide / near / insert / left / right` 五档，挂在 `.vn-scene` 的 CSS 变量上 |
| 逐字 + AUTO + 记录 + 跳过 | 全部有；标点后停顿 76ms；Esc 跳过整场 |
