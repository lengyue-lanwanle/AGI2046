**底子是好的，但有一处会让人弃档的死局、四个技能的关键分支从未生效、验收脚本已经失效。**

## 3. P0 · 必须修（会让人弃档 / 内容完全无效）

### 3.1 战斗死局：医疗机 + 重甲，无撤退，永不结束 ★最严重　`已修复`

**复现（`tools/audit/StalemateProbe.cs`，确定性，30 秒跑完）**

```
轮次    医疗机HP   宪章HP
1       14/16      50/50
2       14/16      49/50
3       16/16      48/50    ← 医疗机把自己奶满，此后血量再没掉过
...
30      16/16      34/50
31      16/16      34/50
FAIL  烧到第 31 轮医疗机仍有 16/16 ——「修复协议」每回合 +9，宪章普攻 9→7（护甲 2），净回血 +2/回合，这一场打不完
```

自动通关里同一组合会一直转下去（实测第 61 轮仍无胜负），因为双方伤害都趋近 0。

**根因（三个叠加，缺一不可）**

1. `e_heal「修复协议」`：`Target=Ally, Range=3, FocusCost=0, Cooldown=0`，每次恢复 **9 HP**，**每回合都能放**。
2. 玩家低伤角色（宪章 H=45，制式霓虹刀）普攻原始 9 点，被护甲 2 削减后**只造成 7 点** → 7 < 9，净回血 +2/回合。
3. **战斗没有任何退出手段**：`web/js/app.js` 里搜不到 flee/retreat，唯一出口是顶栏 ⟲「放弃当前行动」——那会删掉整个存档。

不止一种队伍踩到：

| 队伍（4 组不同组合） | 种子 | 卡住的战斗 |
|---|---|---|
| 宪章 + 白垩（2 人） | 2046 | 巡逻哨兵(22) + 医疗机(14) |
| 疾风 + 白垩 + 星轨 + 天秤（4 人） | 12345 | 巡逻哨兵(22) + 医疗机(14) |
| 文心 + 矩阵 + 万相 + 幻乐（4 人） | 12345 | 重装守卫(32) + 医疗机(14) |
| 疾风 + 文心 + 万相（3 人） | 777 | 轨道守卫(1) —— 只剩 1 HP 也打不死 |

**修法（三选二即可解决，建议全做）**

```csharp
// A. 给敌方治疗加上限（最小改动，1 行）
S("e_heal", "修复协议", "enemy", ..., 0, /* Cooldown */ 2, TargetType.Ally, 3, ...);

// B. 伤害下限：让"打不动"变成"打得慢"
// CombatEngine.ResolveAttack
var damage = Math.Max(0, raw - (int)Math.Round(mitigation));
if (hits > 0) damage = Math.Max(1, damage);   // 至少 1 点/次命中

// C. 加撤退动作（同时补 UI 按钮）
// GameEngine.ApplyAction 新增 case "retreat"
//   - 仅战斗阶段；消耗当前单位整个回合
//   - 全队退回进入战斗前的节点（NodeId = 上一次记录），节点不变 Cleared
//   - 代价：全队 -10% MaxHp、队伍生命 -1（可选）
//   - 战斗面板左下角加「撤离」按钮
```

**验收**：`StalemateProbe` 从 FAIL 转 PASS（30 轮内击杀医疗机）；浏览器里对同一场战斗点「撤离」→ 回地图、节点未清空、AP 归零、不删档。

> 数据补充（`BotSim`，机器代理，不代表人类体验）：单人 3/3 通关；2–4 人 0/9（4 局死局 + 5 局战败）。
> 单人反而更稳，因为 2 人队要面对 `min(4, 人数+1)=3` 个敌人（每名玩家 1.5 个），是全游戏**最陡的比例**。

### 3.2 四个技能的关键分支永远不触发（长夜 2/3 技能是空壳）　`已修复`

**证据（`DataAudit` B 段）**

```
FAIL 效果「rewind」能真正触发 —— kimi_u 的 Special 是 null，引擎 if (skill.Special == "rewind") 永远不成立
FAIL 效果「copy_ally」能真正触发 —— kimi_1 同上
FAIL 效果「dash」能真正触发 —— mistral_1 同上（伤害仍生效，只是不冲锋）
FAIL 效果「retreat」能真正触发 —— rwkv_2 同上（伤害仍生效，只是不后撤）
```

`GameData.Characters.cs` 把这四个效果写进了 `Effects`（`E("rewind")`），而 `CombatEngine` 判的是 `skill.Special`。
整个数据库里只有 3 个首领技能写过 `.Special = "boss_*"`。

**实际观感**

- **长夜**：`kimi_1 借阅` → 选目标、扣 1 Focus、结束回合、**什么都没发生**；`kimi_u 上下文回滚` → 同样空转（测试里施放后 round 仍是 1、长夜 HP 38，完全没有回滚）。技能描述还在 UI 上写着"复制上一名友军使用的技能并立即释放"。
- **疾风**：`疾风突袭` 不贴身也能放，只是没有突进位移——玩家会以为技能坏了。
- **渡鸦**：`渡鸦俯冲` 不后撤。

**修法**

```csharp
// GameData.Characters.cs：补 Special（最小改动）
S("mistral_1", ...).Special = "dash";
S("rwkv_2", ...).Special = "retreat";
S("kimi_1", ...).Special = "copy_ally";
S("kimi_u", ...).Special = "rewind";

// 并在 S() 里加一道启动期断言，防止再犯：
foreach (var fx in new[]{"dash","retreat","rewind","copy_ally"})
    foreach (var sk in Skills.Values.Where(x => x.Effects.Any(e => e.Type == fx)))
        if (sk.Special != fx) throw new InvalidOperationException($"{sk.Id} 的 {fx} 写在了 Effects 里，引擎读不到");
```

**验收**：`DataAudit` B 段 4 项转 PASS；`kimi_u` 施放后 `combat.round == 1 && 长夜.hp == 1`。

### 3.3 官方验收脚本已失效（`browser-e2e` 跑不完）　`未修复（见 §9）`

**实测**：`PARTY=4 node tools/e2e/browser-e2e.mjs` → 5 分 41 秒、275 步、进程被杀时仍停在 `act=1 round=2 combat-end-turn`。

**根因**：`app.js:1793` 一旦 `window.Battle3D.render(...)` 成功就把 DOM 网格 `hidden`，而 `browser-e2e.mjs` 全程靠 `.hex-cell.reachable` / `.unit-token.targetable-unit` 点击。
3D 模式下这两个选择器**根本不存在**（`dom-probe` 实测：`hexCells: 0, unitTokens: 0`），脚本于是每步只能「结束回合」。

**修法**：照 `aoe-ui.mjs` 的写法派发 `battle3d-pick` 事件（`{detail:{col,row}}`），或让 3D 层在 canvas 上盖一层透明可点网格（顺带解决无障碍/自动化）。

**顺带**：`docs/ISSUES.md`「4 人浏览器 e2e（461 秒通关）」这条验收记录应作废或重跑。

## 4. P1 · 功能失效与安全

### 4.1 联机鉴权可绕过（房间成员能操作别人的角色）　`已修复`

**证据（`auth-probe.mjs`，全部实跑）**

```
A. 客人不带 roomCode 操作 p1  → 200 "轮到 宪章 行动。"   ← 越权成功
B. 无凭证读状态              → 200 95 个节点
C. 房间轮询返回 sessionId     → c78cbb8d34e2            ← 上面两条的入口
D. 带 roomCode 越权           → 403 不能操作其他玩家的角色。（正常）
E. 无凭证 DELETE /api/session/{id} → 200                 ← 任何人可删任何对局
```

`/api/action` 只有在带 `roomCode` 时才做身份校验；而 `sessionId` 是公开下发给每个房间成员的。
任何成员只要把 `roomCode` 去掉，就能替别人移动、放技能、结束回合。

**修法**（`Program.cs`）

```csharp
// 1) 记录 sessionId → roomCode 的绑定；请求里 session 属于某房间时强制要求 roomCode+token
if (rooms.Values.Any(r => r.SessionId == request.SessionId) && room is null)
    return 403 "这局属于联机房间，请带上房间凭证。";
// 2) /api/state 要求 token（或只对房间成员开放）
// 3) DELETE /api/session/{id} 加一个环境变量口令，或干脆只允许本机
```

### 4.2 废弃服务器的属性加成完全不生效　`已修复`

```csharp
// GameRules.RecalculatePlayer
p.BaseStats = Stats.Sum(def.Stats, p.ServerBonus);   // ← 有
p.Stats     = Stats.Sum(def.Stats, gearStats);       // ← 漏了 ServerBonus
```

**实测**：`ServerBonus.Vit += 5` → `Stats.Vit` 58→58，`MaxHp` 40→40，只有 `BaseStats` 变成 60。
而命中/伤害/生命/闪避/MaxFocus **全部读 `p.Stats`** ⇒ 每幕 9 台服务器里 6 台"属性服务器"给的是**纯展示数值**。

**修法**：`p.Stats = Stats.Sum(def.Stats, p.ServerBonus, gearStats);`（1 行）

**验收**：接入生体服务器后 `MaxHp` / 命中率有可见变化；`systems-check` 补一条断言。

### 4.3 敌人 Focus 恒为 0 → 两个敌方技能永久禁用　`已修复`

`e_shield_ally`（镜面禁卫「镜墙」，2 Focus）、`e_mark_shot`（白噪天使「标记载入」，1 Focus）在 `TakeEnemyTurn` 里被 `enemy.Focus >= s.FocusCost` 直接过滤掉，而 `CombatUnit.Focus` 对敌人从未初始化（=0）。

**修法**：召唤/生成敌人时 `Focus = 3, MaxFocus = 3`；或把这两个技能 `FocusCost` 改 0。

### 4.4 刷新/重启后「上下文回滚」快照丢失　`已修复`

`CombatState.StartUnits` 标了 `[JsonIgnore]` ⇒ 存档往返后为空 ⇒ `RestoreSnapshot` 里的
`if (startUnits.All(u => u.Id != caster.Id)) return;` 直接返回。**但 Focus 和终极技次数已经扣掉了。**

**修法**：`StartUnits` 改成可序列化的精简快照（id/hp/pos/status），或施放前检查快照是否可用，不可用就报错不扣费。

### 4.5 觉醒节点对未觉醒玩家抛错，且错误路径已改状态　`已修复`

```csharp
if (!string.IsNullOrEmpty(state.AwakenedPlayerId))
{
    node.Cleared = true;                      // ← 先改状态
    throw new GameException("这段回响已经跟着别人走了。...");  // ← 再抛
}
```

玩家每点一次弹一次红错；因为抛异常，`Revision` 不增、存档不写，但内存里节点已 `Cleared` ⇒ **内存与磁盘分叉**。

**修法**：改成 `state.Message = "..."; return state;`（不抛），并把"先判断后修改"作为规则层约定。
