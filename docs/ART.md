## 1. 生成管线

### 1.1 关键教训：`background: transparent` 不可靠

第一次直接传 `background: "transparent"`，拿回来的是 **RGB 图 + 画进像素里的棋盘格**，
右下角还有「AI生成」水印。也就是说透明通道根本没生成。

所以改成 **纯色背景 + 后期抠色**：

```
prompt 里显式要求：纯品红色（#FF00FF）或纯绿色（#00FF00），背景完全均匀、无渐变、无地面阴影
```

背景色按角色主色轮换（粉/红角色用绿幕，其余用品红），避免「主角和背景同色」导致抠色误伤。

### 1.2 风格锁定

22 张必须是同一套语汇，所以 prompt 用固定前缀 + 只替换角色描述：

```
Q版（2.5头身）赛博朋克敌人立绘，全身，粗黑描边，赛璐璐平涂，轻微霓虹边缘光。
角色：{描述}。
要求：纯{品红/绿}色纯色背景（#FF00FF/#00FF00），背景完全均匀无渐变、无地面阴影、无边框；
主体完整不裁切，居中，四周留较多边距。
```

选择 chibi 是因为**玩家的战斗立绘就是 chibi**（`portraits3d/*.png`），敌人必须同一套比例才不违和。

### 1.3 落地处理（`tools/art/keyout.py`）

1. **裁掉底部 5%**：生成器固定在右下角打「AI生成」水印，裁掉最省事。
2. **flood fill 从边缘找背景**，不是全图按颜色替换——
   这样「粉色哨兵站在品红背景上」也不会把装甲吃掉，因为装甲被描边包住，不与边缘连通。
3. **去溢色只在边缘带做**：把透明区外扩 2px 得到窄带，只在这一带把被背景污染的通道压回去。
   全图去溢色会把粉色装甲洗白，所以必须限制在边缘。
4. **羽化 + 收紧**：`GaussianBlur(0.7)` 后把 alpha < 36 归零、> 210 归满，压掉锯齿。
5. **自动裁到主体外框，统一高 640px**，放进 525×640 透明画布——保证 22 张在棋盘上一样高。
6. **转 WebP q88**：22 张共 **1.5MB**（PNG 要 8MB+）。

### 1.4 一个踩坑：并发生成会互相覆盖

生成器用「prompt 前缀 + 时间戳」命名。同一秒提交的两个请求如果前缀相同，**会写成同一个文件**，
先完成的被后完成的覆盖。这一批丢了 2 张（拍卖人、执剑者），重跑时把敌人 id 写进 prompt 开头
（`e_blade_zero_art：...`）才彻底解决。

## 2. 接入

`web/js/battle3d.js`：

```js
// 优先专属立绘，缺图自动退回旧的阵营色占位图
const ENEMY_ART = {};
function enemySpriteFor(u) {
  const id = u.enemyId || '';
  if (id && ENEMY_ART[id] !== false) return ENEMY_ART[id] || (ENEMY_ART[id] = `assets/enemies/${id}.webp`);
  ...按 hue 选 enemy_red/yellow/green/blue...
}
```

配套三处调整，都是**为了「能看清」而不是「好看」**：

| 调整 | 原因 |
|---|---|
| 加载失败回调里把 `ENEMY_ART[id] = false` 并加载退路 | 否则缺一张图 = 一个隐形单位 |
| 立绘尺寸 `1.14×1.40`、中心 `y=0.71`（占位方块仍是 `1.0×0.72`） | 竖版 chibi 与横版方块比例不同，按来源区分 |
| 名牌 `y` 从 1.32 抬到 1.62（仅专属立绘） | 立绘头顶到 1.41，名牌继续挂在原高度会盖住脸 |

### 2.1 加了一层阵营色光晕

深色棋盘 + 深色立绘会糊在一起（黑客幽灵尤其明显）。所以每只敌人背后加一层加色混合的柔光，
颜色取敌人的 `color` 字段：

```js
halo.scale.set(2.15, 2.05, 1); halo.position.y = 0.72;
halo.material.blending = THREE.AdditiveBlending; halo.material.opacity = 0.46;
```

这同时强化了「颜色 = 阵营」的编码——玩家不用读名字也能分出威胁。

标题页的立绘墙保留，但压到 `opacity .32` 当档案底纹——它是「16 个执行体」的索引，
不该和主视觉抢第一眼。

### 4.2 生成：一次只生成一张

`ImageGen` 的 `output_dir` 参数**没有生效**，7 张图全部落进同一个目录；
文件名是「prompt 前缀 + 时间戳」，同一秒内的两张会互相覆盖。
第一轮的 7 张丢了 1 张（第二幕），而且无法从文件名分辨谁是谁。

因此改为**串行**：生成一张 → 立刻 `mv` 成 `key-*.png` → 再生成下一张。
提示词开头加唯一标识（`TITLEKEY_ART` / `ACT2KEY_ART`）只解决「看得出是哪张」，不解决覆盖。

### 4.3 风格锁定

统一前缀（保证 7 张是同一套语汇）：

```
Cinematic cyberpunk key art, painterly anime illustration, neon noir,
deep navy shadows, cyan and magenta rim light, rain and atmospheric haze,
high detail, no text, no letters, no watermark, no logo.
```

三张幕间图刻意用**不同主色**区分地点：霓虹港（青+洋红，街道）、
镜海穹顶（紫+冷青，水面倒影）、零号轨道（白+红警示，真空）。

### 4.4 后期：`tools/art/keyart.py`

| 步骤 | 做法 | 原因 |
|---|---|---|
| 裁水印 | 底部 6% 直接裁 | 生成器固定在右下角打「AI生成」 |
| 擦标题字 | 只对左上角 30%×11% 做中值滤波 + 羽化贴回 | prompt 写了 `no text`，标题图还是被加了「NEON HARBOR 2046」；中值滤波吃掉细笔画，保留雨丝和辉光条纹 |
| 比例 | 标题 1600×900、幕间 1280×720、首领 760×1013 | 页面里不再二次裁切，Boss 竖图刚好填满右侧 62% |
| 暗角 | 径向渐变压角 45–60% | 收视线，顺手掩盖生成图边角 |
| 输出 | WebP q82–84，7 张共 **969KB** | 主视觉是首屏资产，超过 1MB 会拖慢标题页 |

标题图的擦字一开始试过「按行取右侧干净列的中位色横向铺满」，结果把顶部一条青色
辉光条纹复制成了整个 768×240 的横条——**补丁必须只作用在文字所在的小矩形**。

### 4.5 接入

```css
/* 标题：主视觉满屏 + 左侧压暗，立绘墙退到 0.32 */
.title-keyart img { animation: keyPan 46s ease-in-out infinite alternate; }

/* 首领：右侧 62%，左缘 mask 渐隐，融进黑场 */
.ce-art { width: 62%; mask-image: linear-gradient(90deg, transparent, #000 26%); }

/* 幕间：满屏，右侧 21vw 的幕数水印 */
.ca-num { font-size: 21vw; color: rgba(122, 208, 255, .085); }
```

首领图按幕取：`boss${act}.webp`——第一幕拍卖人、第二幕镜面执政官、第三幕零号主脑，
和 `GameData.Acts.cs` 的 Boss 组一一对应（这个映射 0.15 才纠正过，之前把普通组
`g_protocol` 当成了第三幕首领）。

### 4.6 道具图标

数据层给的是字形（`✚ ◈ ❖ ▣ ➤`），在测试机上 `⚔` 曾经被渲染成 `×`，字形不可靠。
5 枚 SVG 沿用既有 UI 图标的 24×24、1.8 描边、圆角端点，用 `mask` 上色：

```js
const ITEM_ICON = { medkit: 'item-medkit', focus_cell: 'item-focus_cell', ... };
// 有 SVG 用 SVG，没有就退回字形
```

这样图标颜色跟着语义色走（治疗青、护盾青、增益琥珀），不需要为每个稀有度再出一套图。

### 6.2 首领场：不要「贴一块立牌」

第一版把 boss key art 当立绘贴在右侧，结果**四条硬边**怎么调都像贴纸
（`mask` 多层叠加在 Edge 上还会算错，只剩一块矩形）。
最后改成：**整幅 key art 直接当 VN 背景**，队伍立绘站在前面，名字牌挂在对话框上。
竖幅图在宽屏会被裁掉上下，所以 `.vn[data-bg^="boss"] .vn-bg` 把 `background-position` 提到 `50% 16%`，
刚好露出骷髅的脸。

### 6.3 `portraits/jev.webp`：0.16 遗留的黑底

16 张立绘里唯一没抠干净的一张（0.16 的记录写「15 白底 + 1 黑底」，那张黑底就是她）。
40px 头像里看不出来，VN 放大到 800px 就是一块黑方块。

诊断过程：`Image.open().convert('RGB')` 四角是 `(0,0,0)`，alpha 全 255；
`keyout.py` 的哨兵色是 `(1,2,3)`，**和黑底差太小，floodfill 认为「已经是填充色」直接返回**，
所以一张都没抠掉，脚本还报了成功。

处理：用纯品红底重新生成同设定立绘（黑长发渐变粉、白羽肩饰、银天平、蒙眼、黑法袍白裙），
再走 `keyout.py`。透明率 70%，无黑边。教训写在 `ISSUES.md`：**哨兵色必须远离背景色**。

## 7. 0.25：portraits3d 与角色的对应性审计

### 7.1 怎么查

`tools/art/audit_portraits3d.py`：从 `GameData.Characters.cs` 读 16 个 `Id` + `Portrait`，
按 `battle3d.js` 的反推规则（`assets/portraits/<id><数字?>.webp` → `portraits3d/<id>.png`）逐个核对，
再看四个指标：文件是否存在、画布是否 512 高、透明像素占比、主体高度占画布比例；
最后列出目录里**没有角色使用**的文件。

| 判定 | 阈值 | 为什么是这个数 |
|---|---|---|
| 底没抠净 | 透明像素 < 20% | 阵营色兜底方块约 1%，正常 285×512 立绘在 30–50% |
| 不像全身 | 主体高 < 画布 70% | 半身裁切顶天 60% |
| 尺寸不齐 | 画布高 ≠ 512 | 尺寸混用会让同一个 sprite 矩形的缩放不一致 |

### 7.2 结果：16/16 名字都对上，但 1 张内容不对

`wenxin.png` 是**半身大头贴**：只有头肩、浅灰不透明底、右下角「千问AI生成」水印，
透明率 **11.96%**、主体却占 96% 高 —— 名字对、图是错的。
它在战斗里就是一块白底大头贴；更麻烦的是 sprite 是固定的 `1.05×1.55` 矩形，
285×512 的源图会被横向拉宽 22%，大头贴等于被拉成一张脸。

其余 15 张全部通过（透明 30–48%，主体高 82–99%），且与 `portraits/*.webp` 的
发型、主色、辨识道具一一对得上（宪章的橙发书、鲸落的鲸尾女仆、天秤的天平、
提灯的灯笼杖、渡鸦的鸦羽、幻乐的玩偶……）。

### 7.3 重画文心：绿幕 + 全局 chroma key

1. **用绿幕不用品红**：她的主色是深蓝，品红会和发色贴近；这也符合 ART.md 的老规矩
   （红/粉角色才用绿幕，其余品红——这里反过来，因为要避开的是蓝）。
   第一次生成给了暗红底 + 洋红边缘光，`flood fill` 只会停在光晕外沿，留一圈红边；
   prompt 加「无边缘光、无辉光」+ 纯 `#00FF00` 重出。
2. **`keyout.py` 不够用**：它从四边 flood fill，只能去掉与画布连通的背景。
   发梢与车轮围出来的**封闭绿洞**会原样留在图上（第一版就是这样，右发梢和踏板下方各一块绿）。
3. 新增 **`tools/art/keyout_green.py`**：按 `G - max(R,B)` 算软 alpha（不看连通性）→
   把 G 钳到 `max(R,B)+8` 去溢色 → 羽化收紧 → 裁到主体、统一 512 高、底部对齐。
   和 `keyout.py` 的分工：**有封闭背景用它，规则形状用它更稳**。
4. 「AI生成」水印在右下角，抠图后把那一小块 alpha 置 0 抹掉——不裁画布，否则会切掉前轮。

结果：`311×512`、透明 30%、主体高 96%，与其余 15 张同一套观感
（坐在轮椅上，比站立角色略矮——这是设定，不是 bug）。

### 7.4 顺手做的两件事

- `battle3d.js` 的立绘 URL 加了 `?v=2`：文件名没变但内容换了，不加版本号老浏览器会继续显示大头贴。
- 审计脚本可随时复跑：`python tools/art/audit_portraits3d.py --strict`（有问题返回非 0）。

### 7.5 目录里那 4 张 `enemy_*.png`

不是角色，是「按阵营色兜底」的旧占位图（圆角方块 + 两个白点）。
22 个敌人现在都有专属立绘 `assets/enemies/e_*.webp`，只有专属图加载失败才会退回它们。
脚本把它们单列为「多余文件」，**保留不动**——删了会让缺图路径变成隐形单位。
