# 0.10.0 方案：支线任务（Side Quests）

> **历史文档，仅作背景。**
> 当前实现状态、验收数字与已知限制一律以 [`HANDOFF.md`](../HANDOFF.md) 和 [`README.md`](../README.md) 为准；
> 本文描述的是当时的计划或审计快照，其中的版本号、文件路径和行为可能已经变化。

> **状态：已于 0.11.0 实施。** 代码见 `GameData.Quests.cs` / `GameEngine.Quests.cs`，验证见 `tools/e2e/quest-check.mjs` 与 `tools/smoke/quest-act.cs`。本文保留为设计原案。
>
> 目标：给 17 层长图加"值得绕一下"的理由，但不改变主线节奏、不引入新战斗系统。
> 原则：**可选、前向、文本驱动、奖励独特但不破坏数值**。

---

## 1. 为什么现在需要支线

现在每幕 95 个节点里，玩家只有一条主线：**打 3 个碎片看守 → 打首领**。其余 90 多个节点都是"顺路的补给"。长图有了长度，但缺少**目标感**——玩家不会为了某件事主动换道。

支线要解决的就是这件事：**给玩家一个自己选的短期目标，并且这个目标会改变他走哪条 lane。**

---

## 2. 三种支线原型

### A. 寻物 · 「还给我」

- 在**遗骸**里捡到一件任务物品（工牌、信、义体零件）
- 带回**任意残响节点**交付
- 交付时弹一张文字卡，讲完这个东西的来历，然后给奖励

> 他手里攥着一张过期的地铁票，日期停在静默之夜。
> 票背面写着一个地址，和一句「如果你捡到这张票，替我去看看」。

### B. 猎杀 · 「清道」

- 本幕内清掉 **3 场战斗**（小战斗/常规/精英都算，权重不同：小战斗 1、常规 1、精英 2）
- 进度实时显示在任务面板
- 完成后到任意残响节点领赏

> 「这一层的巡逻队换班了三次。第三次的时候，我认出其中一台是我以前的同事。」

### C. 探索 · 「测绘」

- 走到**第 N 层**并接入**旧网终端**（或用一次终端）
- 奖励是**追踪 +3**——把绕路花掉的时间还给你

> 「地图不是给活人看的。是给下一个来的人看的。」

---

## 3. 每幕两条，共六条

| 幕 | 支线 | 类型 | 目标 |
|---|---|---|---|
| 一 | 还给我 | 寻物 | 在遗骸里找到工牌，带回残响 |
| 一 | 清道 | 猎杀 | 清掉 3 场战斗 |
| 二 | 请柬上的名字 | 寻物 | 找到 2 件镜面遗物（宝库/遗骸） |
| 二 | 静默的宾客 | 猎杀 | 击败 1 名碎片看守或精英 |
| 三 | 最后一班车 | 探索 | 抵达第 15 层并接入终端 |
| 三 | 备份 | 行动 | 在 2 台服务器上完成写入 |

- 每幕 **2 个残响节点**，固定在第 **4 层与第 13 层**（(4,0) 与 (13,4)），道按幕轮换
- 每幕的 2 条支线都由**先遇到的残响**发放，第二个残响负责**交付**
- 支线**只在本幕有效**，换幕自动失效，不惩罚、不弹失败提示

> 为什么不用"回城交付"：17 层地图上回头一次要花 6–10 格追踪，玩家会直接放弃。所有目标都在前方，交付点也只有一个，且**任意残响都能收任意支线**。

## 4. 奖励设计

| 类型 | 奖励 |
|---|---|
| 寻物 | 该幕稀有装备 ×1 + 80 记忆币 |
| 猎杀 | 消耗品 ×2（随机）+ 120 记忆币 |
| 探索 | **追踪 +3** |
| 行动 | **团队生命 +1**（上限 5） |

**完成 4 条以上**：结局面板追加一段文字——「城市记得你们做过的事，虽然它不打算告诉任何人。」不加任何数值。

> 奖励刻意避开"大量记忆币"：记忆币已经偏多（自动流程结束剩 2900+）。支线给的是**独特的东西**：装备、道具、时间、命。

## 5. 数据与流程

```
NodeType.Echo（残响）
  └─ NodeState.QuestId

QuestDef     Id / Act / Kind / Title / Giver / Objective / Body
             TargetCount / RewardMemory / RewardItem / RewardConsumable
             RewardPurge / RewardTeamLife

QuestState   QuestId / Status（Offered｜Active｜Done｜Claimed）
             Progress / AcceptedRound

GameState.Quests            List<QuestState>
GameState.PendingQuestOffer QuestDef?
```

流程：

1. 玩家站在残响节点上点「互动」→ 前端弹任务卡（接 / 不接）
2. 接受后 `Status=Active`，任务面板出现进度
3. 进度钩子：`Move`（探索类）、`WinCombat`（猎杀类）、`GrantItem/LootCorpse`（寻物类）、`UseServer`（行动类）
4. 进度达成 → `Status=Done`，地图上的残响节点亮起「可领取」
5. 在任意残响领赏 → `Claimed`，发放奖励
6. 换幕时未完成的支线直接清除

## 6. 地图与 UI

- 残响节点图标：`✦`，青紫色，和服务器（`▣`）、宝库（`▣`）区分开
- 有可领取的支线时，地图上所有残响节点加一层脉冲光
- 右侧 INTEL 面板新增「支线」区块，最多显示 2 条，带进度条
- 任务卡沿用现有 `story-card` 版式（标题 + 正文 + 两个按钮）
- 交付时再弹一张卡，文字是该支线的结尾

## 7. 对现有节奏的影响

| 项 | 变化 |
|---|---|
| 每幕节点数 | 95 不变（把 2 个空地改成残响） |
| 空地占比 | 12.6% → **10.5%** |
| 事件占比 | 9.5% 不变 |
| 主线 | 完全不受影响，支线全跳过也能通关 |
| 追踪压力 | 不变；探索类支线反而返还 3 格 |
| 机器人/E2E | 不用改，忽略支线即可 |

## 10. 三个要你拍板的问题

1. **支线要不要"失败惩罚"？** 我建议不要——本幕结束自动失效，不扣任何东西。长图已经够紧，再惩罚会让人不敢接。
2. **奖励要不要允许"追踪 +3"？** 这是我唯一想给"时间"的地方。它不破坏战斗数值，但会让速通更容易。你如果觉得不该动追踪，我换成 60 记忆币。
3. **完成 4 条给结局追加一段文字**，要不要做？纯文本、零数值，我觉得很值。
