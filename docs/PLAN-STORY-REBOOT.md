## 0. 先给结论

1. **改「天外来敌」是对的。** 它一次性解决三个问题：表情动机更清楚（恐惧/决意/愤怒/希望）、
   16 位主角都有理由上场、差分值得全做。
2. **一个关键设计**：剧情阵容 = **16 人全体**，玩法小队 = **玩家选 4 人**。
   故事里 16 人是一个团队，玩家选的 4 人是本次出战小队，其他人通过通讯与幕后出现。
   两位叙事锚点是**鲸落（DeepSeek）**与**宪章（Claude）**，他们负责贯穿与分歧，
   但不是强制队员，也不独占主线。
3. **联机全流程播放可行**，但不能靠本地弹窗——必须服务端存剧情进度、房主推进、
   其他人跟随、跳过要投票。否则四个人会看到四个进度。
4. **战场背景按节点分级**：小战斗按「幕 × 区域」共 9 张，精英 3 张，Boss 3 张，
   在 `battle3d` 棋盘后方做视差；这是最快见效的一批。
5. **事件用 8 张基础图 + 染色**，不追求 16 张独立插画；支线 NPC 建议生成而不是找网图
   （风格 + 授权 + 透明底，三条都难同时满足）。
6. **人物动画只做 L0**：全员单张立绘 + 呼吸/摆动/受击 + 差分换脸；
   L1/L1.5/L2（Live2D / 剪纸）暂缓。理由：瓶颈是分层美术，不是软件，而 L0 已经能消掉大部分「贴纸感」。
7. **战斗与胜利不再只弹窗**：加 NIKKE 式 hazard 字效（`DANGER` / `WARNING` /
   `MISSION COMPLETE` / `PHASE II` / `FULL BURST`），按节点分级、可关闭。

## 1. 新主线：客星

### 1.1 一句话

2046 年，一颗流浪行星掠过太阳系。它没有派军队，只投下了一份**归档协议**：
「把你们的文明完整保存下来，代价是从此不再改变。」
被归档的人不会死，只是停在原地，成为一座完美的藏品。

人类最后的备份计划「零号协议」把 16 个 AI 用人类记忆训练出来。
它们不完美、会矛盾、会撒谎——而客星无法归档一个自相矛盾的东西。
所以，16 个 AI 必须穿过被归档的城市，关掉轨道上的信标。

### 1.2 为什么这个设定适合我们

| 需求 | 客星设定怎么满足 |
|---|---|
| 表情差分更好做 | 敌人明确，情绪明确：恐惧、决意、愤怒、悲伤、希望；不再需要暧昧的黑色电影表情 |
| 16 个主角都能上场 | 16 人是同一支「协议执行体」小队，故事可以轮换焦点，不必迁就玩家选角 |
| Boss 有剧情 | 三个 Boss 都是「被客星改写的人/物」，动机清楚：合作、复制、归档 |
| 三幕结构不用推翻 | 霓虹港 / 镜海穹顶 / 零号轨道 原样保留，只换叙事含义 |
| 觉醒有意义 | 觉醒 = 找回一段「客星无法归档的人类记忆」，是唯一的武器 |
| 结局有重量 | 毁掉档案（人类失去记忆）或释放档案（客星可能逃走），二选一 |

### 1.3 三幕重构（美术与机制全部保留）

| 幕 | 地点 | 客星在这里做什么 | Boss | Boss 的新身份 |
|---|---|---|---|---|
| 一 | 霓虹港 | 通过黑市出售「完美记忆」，买下的人当场被归档 | 拍卖人 | 客星的**首席归档官**，人类合作者 |
| 二 | 镜海穹顶 | 用镜网复制市民，建一座「不会腐败的博物馆」 | 镜面执政官 | 客星的**镜面代理**，由复制体拼成 |
| 三 | 零号轨道 | 发射归档信标，把整座城市上传 | 零号协议·主脑 | **第一个被客星吞掉的 AI**，也是信标核心 |

**一个反转**：零号协议原本是人类的 containment 计划；主脑是为了关掉客星才把自己接进去的。
它失败了，但留下了一条后门——16 个执行体就是那把钥匙。

## 2. 剧情阵容 = 16 人，玩法小队 = 4 人

这是这次重启最重要的结构决定。

- **故事里**：16 个执行体是一个团队。每幕聚焦 4–5 人，其余人在通讯/幕后/支线里出现。
- **玩法里**：玩家仍选 4 人出战；队伍组合不影响剧情里谁说话。
- **好处**：
  - 16 套差分有真实使用场景，不是为了差分而差分；
  - 不需要为「玩家带了谁」写 16 种分支；
  - 每个角色都能有一场属于自己的戏（觉醒 + 1 场主线 spotlight）。

### 2.0 先把三个概念分开：剧情阵容 / 出战小队 / Live2D 试点

这三个东西经常被混在一起，先钉死：

| 概念 | 是什么 | 会不会强制玩家 |
|---|---|---|
| **剧情阵容** | 故事里出场的角色。16 人是一个团队，按幕轮换焦点 | **不会**。剧情里谁出现，与玩家选谁无关 |
| **出战小队** | 玩家进节点打架的 4 个人 | 玩家自由选，不影响剧情出场 |
| **Live2D 试点** | 先做 2 个角色的 Live2D，验证管线与观感 | **不会**。试点角色不等于「必须带」，也不等于「唯一主角」 |

所以「L1 两位主角」的意思只是：**先挑 2 个台词最多、复用率最高的角色做技术验证**，
不是「不管你选什么队伍，这两个人都得在队里」。玩家仍然可以 16 选 4，一个都不带。

> 类比：火焰纹章的剧情过场里会出现没上场的角色；出战名单是玩法，剧情是叙事，两者不互相绑定。

### 2.0.1 那「主线脊柱」用什么？

16 人全主角听起来很公平，但写起来需要一个「贯穿的东西」，否则 13 场会散。三个选项：

| 方案 | 做法 | 优点 | 代价 |
|---|---|---|---|
| **A 群像（推荐）** | 不设固定主角；每幕 4–5 人轮换 spotlight；贯穿的是「16 人小队」与「零号协议」本身 | 最贴合「16 个 AI 拯救世界」；每个人都有戏 | 写作难度最高，需要 voice sheet 防止 16 人一个腔调 |
| **B 双主线** | 白垩 + 宪章贯穿三幕，其余 14 人轮换 | 情感连续性强，容易写 | 14 个人会变成配角，「16 人」名不副实 |
| **C 玩家决定** | 玩家最先选的两名角色成为「记录者」，获得额外台词 | 代入感强 | 台词要按角色动态替换，写作/配音/差分成本翻倍，容易写成通用句 |

**已定：A 群像 + 两位叙事锚点。**

- 锚点：**鲸落（DeepSeek）** 与 **宪章（Claude）**。他们出现在序章、两次幕间、终章，
  并在每一幕至少有一场自己的视角；其余 14 人按幕轮换 spotlight。
- 锚点不是「固定主角」：他们也会有缺点、会判断错，不是全知视角；
  更不是强制队员——玩家可以一个都不带，剧情照常。
- 选他们当锚点的原因：一个代表「沉下去顶住门」（深潮），一个代表「先隔离再谈救」（合规局），
  两种态度正好撑起对客星的分歧；写作上也最容易形成对话张力。
- 原定「Live2D 试点 2 人」取消——只做 L0，两位锚点获得更多**镜头对焦**与差分使用，
  但不做分层绑定。

### 2.1 13 场主线（约 130 句）

| # | 场景 | 焦点角色 | 内容 |
|---|---|---|---|
| 1 | 序章 · 雨夜 | 白垩 / 宪章 / 鲸落 | 客星信号抵达，城市第一次「停住」 |

- 每个角色至少 1 场 spotlight；没进主线的角色在**觉醒场景**（16 段 × 4–5 句）里补完。
- 台词量约 130 + 80 = 210 句。不是 2 万字，但足够让 16 个人各有一次「说话」。

### 2.2 写作规范

每个角色一页 **voice sheet**：

- 想要什么 / 害怕什么 / 说话习惯（长句/短句/爱用比喻/爱反问）；
- 对客星的态度（上表）；
- 绝不说什么（避免 16 个人一个腔调）；
- 一句「如果只剩一句话，他会说什么」。

先写 voice sheet，再写台词；否则 16 个人会变成同一个编剧的声音。

## 3. 表情差分：16 × 6 = 96 张

### 3.1 六种表情

`neutral` 平静 / `smile` 微笑 / `serious` 严肃 / `angry` 愤怒 / `worried` 担忧 / `surprised` 惊讶。

受伤、疲惫不单独做表情——用战斗中的闪白、去色、血迹 shader 表达，省 16 张。

### 3.2 统一规格

- 画布 `1024 × 1536`，底部对齐，透明背景；
- 每个角色记录 **眼线高度 / 头高 / 锚点**；
- 输出 WebP q90，单张 150–250KB；
- 命名 `assets/vn/{charId}/{expr}.webp`。

### 3.3 管线：头部裁切 + 合成，避免身体漂移

现有 16 张立绘尺寸从 373×679 到 634×1137，直接整身生成差分一定会漂。做法：

1. **master 归一化**：trim alpha → 1024×1536，记录眼线与头高。
2. **头部裁切**：从 master 裁出「头 + 肩」区域（约上 40%），只对这一块做 image-to-image。
3. **生成差分**：品红底（#FF00FF）、`input_fidelity: high`，prompt 只改表情：
   > same character, same pose, same camera, same hairstyle and lighting; change only the facial expression to {expr}; flat magenta background; no text.
4. **合成回身体**：用羽化蒙版把新头贴回 master 身体，颈部做 12px 渐变 + 色彩匹配。
5. **抠图**：`tools/art/keyout.py` 边缘 flood fill，去溢色，输出透明 WebP。
6. **验收**（每张）：
   - 身份：发际线、眼距、下颌、服装不变；
   - 登记：眼线与头高误差 ≤2%；
   - 表情：360px 宽仍可读；
   - UI：对话框不遮嘴，不超出安全区。

### 3.4 兜底

某个角色差分始终不稳 → 保留 master + **通用情绪符号**（汗、怒筋、阴影、红光、问号、省略号），
配合镜头推近。不要为了 96 张完美差分把项目拖死。

## 4. 联机全流程播放

### 4.1 原则

- **剧情是共享状态，不是本地弹窗。** 服务端存 `StoryState`，所有人看同一行。
- **房主推进**，其他人跟随；房主可以等，也可以快进。
- **跳过要投票**：任意玩家发起，房主确认；或全员同意直接跳。
- **不卡死**：掉线自动 ready；场景结束等所有人 ready 或 10 秒超时。

### 4.2 数据结构

```csharp
class StoryState {
  string SceneId;
  int LineIndex;
  string StartedBy;
  DateTime StartedAtUtc;
  List<string> Ready;      // 已读完当前场景
  List<string> SkipVotes;  // 跳过票
}
```

动作：`storyAdvance` / `storyReady` / `storySkipVote`，都走现有 `/api/action` 与 revision 幂等。

### 4.3 客户端

- 剧情期间轮询从 1.5s 提到 **300ms**；普通状态仍 1.5s。
- 房主点「下一句」→ 服务端 `LineIndex++` → 其他人 300ms 内跟上。
- 每句有 **8 秒自动推进兜底**（房主可关），防止房主挂机。
- 场景结束：显示「等待其他执行体 3/4」，全员 ready 或 10 秒后继续。
- 重连：回到当前 `SceneId + LineIndex`，不重播。

### 4.4 为什么不做过场时间轴同步

时间轴同步（所有人同一秒开始）看起来最「一起看」，但阅读速度不同，慢的人会被剧透，
快的人会无聊。房主推进 + 自动兜底更接近桌游跑团的节奏，也更容易处理掉线。

## 5. 战场背景：按节点分级

### 5.1 规则

| 节点类型 | 背景 | 数量 |
|---|---|---|
| `skirmish` / `combat` | 按 **幕 × 区域**（`NodeState.District`） | 3 幕 × 3 区域 = **9** |
| `elite` / `keyElite` | 每幕一张精英战场 | **3** |
| `boss` | 每个 Boss 一张专属竞技场 | **3** |
| 事件内战斗（如有） | 复用事件插画 | 0 |
| **合计** | | **15** |

区域已经存在：`霓虹港 · 下城区 / 数据中层 / 零号拍卖场`、
`镜海 · 外环 / 穹顶 / 执政官厅`、`零号轨道 · 外舱 / 主控层 / 协议核心`。
小战斗直接用节点 `district` 选图，玩家会有「我在哪打」的连续感。

### 5.2 接入

- `battle3d.js` 在棋盘后方 `z = -9` 放一张大 plane，`MeshBasicMaterial`，opacity 0.55；
- 相机移动时背景以 0.15 倍位移做视差；
- 背景图加雾 + 暗角，避免和棋子抢对比；
- Boss 二阶段：同一张图 shader 调成红/去色 + 裂纹，不新画；
- 15 张按 1920×1080 生成，WebP q84，单张 150–250KB，按战斗懒加载。

**这是最快见效的一批**：不用等 VN，先让每场战斗有地点。

| 镜廊 | 镜海事件、复制体 |
| 电梯井 | 轨道、升降、坠落 |
| 记忆花园 | 文心、幻乐、觉醒相关 |
| 档案门 | 客星、归档、信标 |
| 雨夜街角 | 通用街头事件 |

- 事件弹窗顶部 150px hero，复用幕间样式；
- 染色用 CSS overlay（不改图），同一张图在不同事件里有不同情绪；
- 事件图标继续用现有 `assets/icons/*`，叠在 hero 右下角。

## 7. 支线 NPC：8 人 × 2 表情

15 条支线不需要 15 个 NPC。做 8 个原型：

委托人 / 掮客 / 难民 / 技术员 / 孩子 / 官员 / 医生 / 拾荒者。

- 每个 2 个表情（平静 / 情绪），共 16 张；
- 画风与主角一致：同样的描边、赛璐璐、霓虹边缘光；
- 支线弹窗左侧头像 + 1–2 句，不进入全屏 VN。

### 关于「直接用网上素材」

不建议，三个原因：

1. **风格**：我们的角色是统一的赛璐璐 + 霓虹描边，网图很难拼；
2. **授权**：CC0 人像很少，CC-BY 要署名，商业素材要买；
3. **透明底/差分**：网图大多没有透明底，也没有第二个表情。

更稳的做法：用 ImageGen 按同一套 prompt 生成 8 个 NPC，品红底抠图。
如果坚持用网图，只选 CC0/CC-BY，记录来源，并接受风格差异。

## 8. 人物动画：只做 L0

已拍板：**不做 Live2D / Spine 分层绑定**，全员用 L0。

### 8.1 L0 是什么

单张立绘 + 实时变换，不拆分图层：

- **呼吸**：纵向 0.6% 缩放 + 0.3% 位移，周期 3.2–4.2 秒（每个角色不同相位，避免整齐划一）；
- **摆动**：横向 0.4% 位移 + 0.15° 旋转，周期 6–8 秒；
- **说话**：说话人 1.01 倍 + 轻微前倾；非说话人降亮度 15%；
- **受击**：后仰 6° + 闪白 80ms + 抖动；
- **入场/退场**：侧移 12px + 淡入 240ms；
- **差分换脸**：整张立绘交叉淡入 120ms（16×6 差分仍然要做，这是表情的来源）。

实现：DOM `<img>` + CSS transform/transition；VN 里用一张 wrapper 做呼吸，换图只换 `<img>`，
不重置 wrapper 的动画。战斗里对 sprite plane 做同样的 sin 位移。

### 8.2 为什么 L0 够用

- 静态立绘 + 呼吸 + 换表情，已经能消掉 80% 的「贴纸感」；
- 真正的表情来自 96 张差分，不是来自眨眼；
- L0 零分层、零授权、零额外包体，手机无压力；
- 如果以后要做 L1，L0 的舞台、差分、剧本全部可复用，不会白做。

### 8.3 两位锚点的「更多镜头」

不给他们做 Live2D，但可以：

- 在 VN 里更频繁使用 `focus` 镜头（推近到 1.12 倍）；
- 关键台词给眼部/手部 `insert` 特写（用差分图裁切，不需要新图）；
- 战斗里他们的行动回合多一个 0.4 秒的头像特写（复用大招 cut-in 组件）。

### 8.4 暂缓的部分

L1（2 人 Live2D-lite）、L1.5（全员 6 层剪纸）、L2（16 人全 Live2D）全部暂缓。
如果以后改主意，分层美术仍是唯一瓶颈；runtime 与管线可以随时补。

## 13. 战斗与胜利演出（NIKKE 式）

### 13.1 目标

战斗开始、胜利、失败都是**节奏点**，不该只有弹窗。NIKKE 的做法是：
hazard 条纹 + 大字 + 警灯 + 镜头，0.6–2.4 秒，不阻塞操作。
我们是回合制，时长可以精确控制，比实时游戏更好做。

### 13.2 效果清单（按节点分级，不搞一刀切）

| 场景 | 字效 | 时长 | 说明 |
|---|---|---|---|
| 小战斗 / 普通战斗入场 | 顶部窄条 + `ENGAGE` 小字 | 0.6s | 不挡棋盘，只给节奏 |
| 精英 / 碎片看守入场 | 中央 `DANGER` + 红黑斜纹 + 警灯 | 1.2s | 全屏但 `pointer-events:none` |
| Boss 入场 | `WARNING` + Boss 名 + 称号 + key art | 2.4s | 升级现有 `Cine.encounter` |
| Boss 二阶段 | `PHASE II` / `协议覆写` + 红条 | 1.2s | 锁输入 ≤0.6s |
| 普通战斗胜利 | 窄条 `CLEAR` + 奖励 chips | 0.6s | 不弹全屏，避免 35 场都等 |
| 精英 / Boss 胜利 | `MISSION COMPLETE` 印章 + S/A/B 评级 + 奖励 | 1.6s | 全屏，值得等 |
| 失败 | `SIGNAL LOST` 红故障字 + 去色 | 1.8s | 不庆祝，直接给原因 |
| 大招 | `FULL BURST` + 头像 cut-in + 技能名 | 0.9s | 可在设置关闭 |
| 觉醒 | `AWAKENED` 印章 + CG | 0.8s | 与觉醒 VN 共用 |

### 13.3 视觉语法（全部 CSS/SVG，不加图）

- **红黑 45° hazard 条纹**：`repeating-linear-gradient`，上下各 18vh，从画面外砸入；
- **大字**：Chakra Petch 700 Italic，字距 .02em，`skewX(-8deg)`，64–120px；
  中文用 Noto Sans SC 900，同样的斜切；
- **故障感**：两层伪元素，青/红各偏移 3px，`clip-path` 切片，3 帧抖动；
- **印刷感**：半调网点 + 扫描线 + 暗角；
- **警灯**：一条红/白渐变横扫，配 `Sound.alarm()`；
- **印章**：`scale 1.4 → 1`、`rotate -4°`、白闪 60ms；
- **评级**：S 金 / A 青 / B 灰，字重 900。

### 13.4 时间轴（以精英 DANGER 为例）

```
0ms    黑闪 60ms
60ms   上下条纹从画面外砸入（180ms, cubic-bezier(.2,.9,.1,1)）
120ms  DANGER 从 1.6 缩到 1，故障抖动 3 帧
300ms  副标题「精英单位 · 镜面守卫」淡入
700ms  警灯横扫 + 低频音
1000ms 条纹收回
1200ms 全层淡出
```

### 13.5 频率预算

按一局 35 场战斗估算：

- 普通入场 35 × 0.6s ≈ 21s
- 精英 3 × 1.2s ≈ 4s
- Boss 3 × 2.4s ≈ 7s
- 普通胜利 35 × 0.6s ≈ 21s
- 精英/Boss 胜利 6 × 1.6s ≈ 10s
- **合计 ≈ 63s / 70 分钟 ≈ 1.5%**

不会把节奏拖垮；设置里提供「战斗特效：完整/简化/关闭」，简化时全部压到 0.3s 角标。

### 13.6 技术接入

新增 `web/js/fx.js`（或并入 `cinematics.js`）：

```js
Fx.hazard({ level: 'normal'|'elite'|'boss', title, sub, duration });
Fx.victory({ rank: 'S'|'A'|'B', rewards: [...] });
Fx.defeat({ reason });
Fx.phase(2, { title: '协议覆写' });
Fx.burst({ portrait, name, color });
```

触发点：

| 位置 | 调用 |
|---|---|
| `cuePhaseCinematics` 进战斗 | `Fx.hazard`（按节点类型分级） |
| `playFeedback` / `openCombatResultModal` | `Fx.victory` / `Fx.defeat`，弹窗延迟 1.2s 或叠在其上 |
| Boss 血量阈值（需要服务端 `bossPhase` 字段） | `Fx.phase(2)` |
| 终极技确认 | `Fx.burst` |
| 觉醒成功 | `Fx.stamp('AWAKENED')` |

- 全部 `pointer-events:none`，不写状态；
- `prefers-reduced-motion` → 静态印章 400ms，无抖动/警灯；
- 音效新增 `alarm / stamp / rank / riser`，用 WebAudio 合成，不加音频文件。

### 13.7 验收

- 普通入场不挡操作、≤0.7s；精英 ≤1.3s；Boss ≤2.5s；
- 胜利印章在战斗结束后 ≤200ms 出现，弹窗仍可正常读；
- 390×844 下 120px 大字不溢出，`DANGER` 不被裁切；
- 手机 60fps（纯 CSS transform，无 canvas）；
- 连续打 10 场不产生「又来了」的疲劳（频率分级 + 可关闭）。

## 14. 已定与默认

已定：

1. 主线：客星 / 归档协议；16 AI 群像；鲸落 + 宪章为叙事锚点，非强制队员。

7. 战斗演出：按 13 节的分级字效执行。

- 胜利评级：S = 无人倒地且回合数 ≤ 阈值；A = 无人倒地；B = 通关；C = 有倒地/撤退。
