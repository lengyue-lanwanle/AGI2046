# 叙事表现力：先分类，再选工具

> **历史文档，仅作背景。**
> 当前实现状态、验收数字与已知限制一律以 [`HANDOFF.md`](../HANDOFF.md) 和 [`README.md`](../README.md) 为准；
> 本文描述的是当时的计划或审计快照，其中的版本号、文件路径和行为可能已经变化。

> 版本：讨论稿（未实施）
> 触发：主线没表现力、精英/Boss 没剧情、二阶段没动画、觉醒没特写、大招没演出、人物不会动。
> 核心判断：**这六个问题不是同一类，不能都用视频解决。** 视频只该出现在第 4 层。

---

## 1. 先承认：现在的「没表现力」是结构问题，不是画质问题

当前叙事只有三样东西：

- 5 张剧情文字卡（开场 / 两幕换幕 / 首次密钥 / 追踪告急）
- 幕间整幅 key art + 一段旁白
- 战斗日志里的文字

角色在剧情里**没有说过一句话**。Boss 从出场到死亡，除了名牌和技能名，没有任何态度。
所以问题不是「画面不够电影」，而是：

> **没有角色在说话，也没有事情在玩家操作的过程中发生。**

这一点不解决，加多少视频都只是「偶尔插播一段漂亮的片子」，玩家仍然记不住谁是谁。

---

## 2. 六个问题，六种工具

| 问题 | 真正的缺口 | 最有效的工具 | 视频是否必要 |
|---|---|---|---|
| 主线没表现力 | 没有角色、没有冲突、没有节奏；信息全在弹窗里 | **写作 + 触发器系统**（Hades 式 barks）+ 少量插画 | 不必要；视频只是点缀 |
| 精英/Boss 没剧情 | 没有名字以外的身份、没有战前/战中/战后的台词 | **Boss banner + 档案 + 阶段台词** | 3 个 Boss 可各配 1 段 5 秒片，可选 |
| 二阶段没动画 | 机制在变，画面没变 | **实时 shader + 镜头 + 场地变化 + 1.2 秒横幅** | **不建议**（会打断战斗、无法反映当前状态） |
| 觉醒没特写 | 觉醒只有文字与技能替换 | **16 张觉醒插画 + 2.5D 推移 + 粒子** | 不必要；插画足够 |
| 大招没演出 | 技能只有数字和特效 | **0.9 秒 cut-in（头像 + 色块 + 技能名）** | 不必要；16 段视频成本高且不可控 |
| 人物不会动 | 战斗立绘是静态 PNG | **程序化呼吸/倾斜/受击 + 少量 Spine/Live2D** | **不建议**（循环接缝、体积、一致性） |

一句话：**视频适合「一次性的氛围段」，不适合「高频、要跟状态同步」的演出。**

---

## 3. 视频到底能不能做幕间？能，但要接受四个硬约束

### 3.1 能力现状（2026）

| 工具 | 单段时长 | 首尾帧 | 参考图 | 原生音频 | 商用 |
|---|---|---|---|---|---|
| 本机 `VideoGen` | 4–30s（模型相关） | 支持 `image` + `last_image` | 首帧图 | 可选 | 本机生成 |
| Kling 3.0/4.0 | 5–15s（可延展） | 支持 | Element Lock | 是 | 付费档 |
| Google Veo 3.1 | 4–8s | 支持 | Ingredients | **最强** | 付费档 |
| Runway Gen-4.5 | 2–10s | 支持 | 角色参考 | 部分 | 付费档 |
| Gemini Omni | 3–10s | 支持 | 1–3 张参考 | 是 | 付费档 |

**成本量级**：外部 10 秒 720p 约 $0.4–1.5/次；按 3–5 次重试算，一个可用镜头 **$2–7**。
本机 `VideoGen` 5 秒约 **50–100 积分**，同样要算重试。

### 3.2 四个硬约束

1. **连贯性天花板 8–20 秒**：再长就会出现手变形、背景漂移。必须按「5–8 秒一个镜头」拆，
   用首帧/尾帧锚定，再在剪辑里拼。不要指望一条 prompt 生成 30 秒完整幕间。
2. **角色一致性**：纯文生视频每次都会重新「解释」角色。必须用现有立绘/ key art 做首帧或参考图；
   跨镜头漂移仍然存在，尤其脸和服装细节。**我们的角色是原创 chibi，风险更高。**
3. **透明通道是陷阱**：WebM VP9 alpha 在 Safari/iOS 上不生效，多个 WebM 还会崩标签页；
   Safari 只认 HEVC alpha（.mov）。**不要做「带透明背景的视频叠在战场上」**，
   要么全屏播放，要么黑底 + `screen`/亮度键，要么干脆用图片。
4. **体积与自动播放**：720p 6 秒 H.264 约 2–5MB；手机必须 `muted` + `playsinline`，
   非静音自动播放会被拦。视频只适合「幕间/开场」这种可以预加载、可以等的时刻。

### 3.3 所以，幕间视频应该这样用

- **形态**：不是「一段 30 秒动画」，而是 **4–6 个 5 秒镜头 + DOM 文字** 的拼贴。
- **内容**：只拍「环境/物件/背影/手」——不拍正脸对话。
  正脸对话交给插画 + 文字，既稳定又便宜。
- **接入**：`<video>` 全屏铺底，文字与按钮仍是 DOM；不要塞进 WebGL 做纹理（多一层解码与兼容问题）。
- **兜底**：视频加载失败/减少动态 → 直接回现有 `Cine.act` 的整幅 key art。
- **触发**：只在「进入下一幕」时播一次，不做每局随机。

**我的结论**：幕间可以上视频，但**最多 2 段**（第一幕→第二幕、第二幕→第三幕），
每段 4–6 个镜头；开场仍建议实时 Three.js（可交互、可停在标题页），不用视频。

## 4. 每一块具体怎么做

### 4.1 主线故事：先把「谁在说话」补上

**不做**：再加 10 张文字卡。
**要做**：

1. **Boss 三部曲台词**：每个 Boss 在「出场 / 血量 75% / 50% / 25% / 死亡」各一句，
   共 3×5 = 15 句。战斗中弹出，不打断操作。
2. **精英身份**：每个精英给「名字 + 一句身份 + 一句威胁」，共 6–9 条；
   击败后掉一枚「记忆碎片」，档案里补一段 80 字。
3. **触发器系统**（Hades 的最小版）：条件 = 幕 / 是否首次 / 队伍状态 / 追踪值 / 击杀数；
   每条台词只播一次，按「最具体优先」排队。先写 60–100 条，够撑 3–5 局。
4. **剧情卡升级**：加说话人头像、逐字显示、环境音；不是加长文本，是加「停顿」。

这一层的成本几乎全是写作与 UI，没有视频，但对「故事没表现力」的改善最大。

### 4.2 Boss 战：用「Boss Banner」而不是长片

参考 Zelda/FFXIV/Bayonetta 的做法：**名字 + 称号 + 一句台词**，2–3 秒，画面冻结或慢镜。

- 入场：现有 `Cine.encounter` 已有整幅 key art，加「称号」与一句台词即可；
- 战中：血量阈值触发台词，屏幕边缘闪一次阵营色；
- 死亡：一句遗言 + 掉落物特写（可用现有插画）。

三个 Boss 各配一段 5 秒视频是**可选增强**，不是必需；先做 banner，性价比高得多。

### 4.3 二阶段：实时，不要视频

**触发**：Boss 血量 ≤ 50%（或护盾破碎），服务端发 `phaseChanged`。

**表现**（总时长 1.4 秒，不锁输入）：

1. 0.0–0.2s：画面短暂去色 + 0.15 倍速；
2. 0.2–0.9s：Boss 立绘 shader 抖动/裂纹/换色，场地环境光切到另一套颜色；
3. 0.5–1.2s：横幅「第二阶段 · 协议覆写」，下面一行台词；
4. 1.2s 后：Boss 技能表切换，音乐加一层。

为什么不用视频：二阶段必须**反映当前血量、当前站位、当前 buff**；
预渲染片段既对不上，又会把 4 人局切成「看片 3 秒」。实时 shader 每次都不一样，且零素材成本。

### 4.4 觉醒：16 张插画，不是 16 段视频

- 用现有立绘做 image-to-image，生成「觉醒态」：同一构图、眼睛发光、回声纹路、背景碎片。
- 16 张，统一 2:3，WebP；比 16 段视频便宜、稳定、可放进档案。
- 演出 1.8 秒：插画从 1.08 推到 1.0，色差 + 粒子 + 名字与「AWAKENED」；可跳过。
- 文字仍是 DOM；插画只负责「那一刻」。

### 4.5 大招：0.9 秒 cut-in

参考 Persona / 原神 / 星穹铁道：**头像特写 + 色块 + 技能名**，不拍完整动作。

- 素材：现有 16 张立绘裁眼部/半身，加一层角色主色渐变与速度线；
- 触发：按下终极技 → 0.9 秒 cut-in → 回到战场结算；
- 可设置里关闭「技能 cut-in」，避免重复战斗疲劳；
- 16 个角色 × 1 张处理图，成本远低于视频，且永远清晰。

### 4.6 人物动起来：先程序化，再考虑绑定

**第一层（零新素材）**：

- 待机：上下 2px 呼吸 + 轻微左右摆（battle3d 里对 sprite 做 sin 位移/缩放）；
- 攻击：前冲已有；加 0.1s 压扁/拉伸；
- 受击：后仰 6° + 抖动 + 闪白；
- 死亡：旋转倒下 + 淡出；
- 脚步：移动时扬尘粒子。

这一层做完，角色就不再是「贴纸」，成本只是几十行代码。

**第二层（要绑定）**：

- Live2D：脸部表情最好，适合对话/觉醒；Spine：全身动作、性能更轻，适合战斗。
- 16 个角色全绑不现实。先选 **2 个主角**做试点，看观感与工作量再决定。
- Web 集成：PixiJS + Spine runtime，或 Live2D Cubism Web SDK；包体 +200KB–1MB。
- **AI 视频循环不推荐**：接缝、体积、每次生成都不一致，16 个角色会失控。

## 5. 如果要做视频幕间：一条可执行的管线

以「第一幕 → 第二幕」为例：

| 镜头 | 内容 | 时长 | 生成方式 |
|---|---|---|---|
| 1 | 拍卖锤落下，锤面裂纹发光 | 5s | 首帧用 boss1 key art 局部 |
| 2 | 邀请函在雨中翻开，字迹被水晕开 | 5s | 首帧新生成静帧 |
| 3 | 镜头穿过镜面，倒影里出现第二幕穹顶 | 6s | 首帧 act2 key art |
| 4 | 黑场，一行字「第二幕 · 镜海穹顶」 | 2s | DOM |

规则：

- 全部 **720p、静音、无字幕、无文字**；文字后期用 DOM 叠；
- 每段首帧先出静帧（ImageGen），确认构图后再 image-to-video；
- 每个镜头最多 3 次重试，仍不合格就换「静帧 + 缓慢推镜」；
- 文件命名 `cine/act2-shot1.mp4`，总大小控制在 **8MB 以内**；
- 播放：`<video muted playsinline preload="metadata">`，进入幕间前预加载；
- 兼容：Safari 用 H.264 MP4；不做透明通道；
- 降级：加载失败/减少动态 → `Cine.act` 静态 key art。

**预算**：4 个镜头 × 3 次重试 × 50–100 积分 ≈ **600–1200 积分/段**（本机）；
外部工具按 $2–7/可用镜头，约 **$8–28/段**。

## 6. 路线图（先做哪一层）

| 阶段 | 内容 | 产出 | 为什么排这里 |
|---|---|---|---|
| **N0 叙事骨架** | 15 条 Boss 台词、9 条精英身份、60–100 条触发台词、剧情卡升级 | 文本 + 触发器 + UI | 没有这一层，视频只是孤岛 |
| **N1 静态特写** | 3 张 Boss 称号 banner、16 张觉醒插画、16 张大招 cut-in、6 张精英档案 | 图片 + DOM 演出 | 性价比最高，立刻可见 |
| **N2 实时演出** | 二阶段 shader、觉醒 2.5D、大招 cut-in、角色呼吸/受击 | Three.js/CSS | 跟状态同步，零视频成本 |
| **N3 视频试点** | 只做「第一幕→第二幕」4 镜头，实测加载/观感/手机 | 1 段 MP4 + 播放器 | 用最小成本验证视频值不值 |
| **N4 角色绑定** | Spine/Live2D 试点 2 个角色 | 2 个可动立绘 | 工作量最大，最后决定 |

**验收**：

- 每个 Boss 有出场/三阶段/死亡共 5 句；每个精英有名字与 1 句威胁；
- 二阶段触发到横幅出现 ≤200ms，输入锁定 ≤0.6s；
- 觉醒 16/16 有插画，演出 ≤1.8s 可跳过；
- 大招 cut-in ≤0.9s，可在设置关闭；
- 视频幕间首帧 ≤1.5s，单段 ≤8MB，降级可用。

## 7. 我的判断（要先说清楚）

1. **视频能做幕间，但不该是第一步。** 先补「谁在说话」，再谈「画面多电影」。
2. **二阶段、大招、觉醒都不该用视频。** 它们要高频、要跟状态同步、要被跳过；
   实时 shader + 插画 + DOM 更稳、更便宜、更清晰。
3. **人物动起来先做程序化。** 呼吸、受击、倒下这些「生命感」不需要绑定，
   做完再判断要不要上 Spine/Live2D。
4. **视频只做 1–2 段幕间 + 可选 Boss 出场。** 用首尾帧锚定、5 秒一镜、全屏不透明、文字交给 DOM。
5. **Hades 的启示不是「写 2 万句」，而是「让角色对玩家刚做的事有反应」。**
   先写 60 条高命中率的触发台词，比 1 段 30 秒视频更能让世界活起来。
